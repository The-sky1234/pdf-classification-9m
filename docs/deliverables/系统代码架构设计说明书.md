# 900万PDF智能分类系统 · 系统代码架构设计说明书

版本 v2.0 ｜ 日期 2026-10-09 ｜ 审阅对象：主管、技术负责人 ｜ 口径：以实际代码为准

## 1 项目概述

本系统面向约900万份PDF文档的智能解析与两级分类，实现"扫描建任务—解析提证据—相关性判断—一级/二级分类—LLM自动复核—持久化—人工复核"全链路。设计目标为单Linux服务器多GPU下的高吞吐、可断点续跑、可审计。

分类体系：4个一级、25个二级（7+3+9+6），以 `contracts/taxonomy.yaml` 与 `GET /taxonomy` 为准。结果状态：CLASSIFIED、IRRELEVANT、MANUAL_REVIEW、FAILED、UNRESOLVED，以 `backend/store.py` 为准。

## 2 总体架构

分层架构图：

```text
┌────────────── 接入层 ──────────────┐
│ Backend API (FastAPI, 8路由, X-API-Key)  任务建模/结果入库/复核/查询 │
└──┬──────────────┬──────────────────┘
   │ PostgreSQL   │ Redis (仅传引用)
   │ doc_tasks/   │ pdf_tasks / classify_tasks / queue:dead
┌──▼──────┐  ┌────▼─────┐  ┌────────▼──────┐  ┌────────────┐
│ Scheduler│  │ Parser   │  │ Classification│  │ DevOps     │
│ Pipeline │  │ Worker   │  │ Worker        │  │ 单机多GPU  │
│ 断点续跑 │  │ 类型路由 │  │ Gate→L1→L2    │  │ Compose编排│
└──────────┘  └──────────┘  │ →Verify→复核  │  └────────────┘
```

PDF处理流程图：

```text
PDF只读挂载 → POST /tasks/scan 建任务(PENDING) → Redis pdf_tasks
→ Parser出队 → 类型判定 → 路由抽取 → FilePayloadStore.save(parse_ref)
→ Redis classify_tasks → Classification出队 → Evidence路由 → Gate
→ L1 → L2 → Verify → LLM自动复核(≤2轮) → POST /results 入库(SAVE/DONE)
→ MANUAL_REVIEW → POST /review/{rid} 人工定稿
```

模块调用图：

```text
scan → store.create_task(幂等uuid5) → Pipeline.run_one(parse_fn→classify_fn→save_fn)
parse_fn=parser.parse_pdf ｜ classify_fn=ClassificationPipeline.run ｜ save_fn=POST /results
```

## 3 核心业务流程

| 流程 | 说明 |
|---|---|
| PDF解析 | 类型判定→后端路由→证据抽取，失败分可/不可重试 |
| Evidence Router | 按类型与标题质量输出 TITLE/BODY/OCR_BODY/VISION 四种证据模式 |
| 相关性判断 | BGE打分+关键词加成，输出 RELEVANT/UNCERTAIN/IRRELEVANT |
| 一级/二级分类 | embedding直判优先，否则LLM约束裁决；二级经reranker重排 |
| LLM自动复核 | 仅候选ID/IRRELEVANT/UNCERTAIN，最多2轮，超时30s×重试2 |
| 持久化与复核 | 结果入库置SAVE/DONE；MANUAL_REVIEW进人工队列 |

## 4 模块设计

### 4.1 Parser（`parser/`）

| 项 | 内容 |
|---|---|
| 职责 | PDF类型判定、抽取后端路由、文本/版面证据抽取 |
| 输入 | 文件路径、ocr_backend、mineru开关、max_pages |
| 核心处理 | detector统计字符/图片数判TEXT/SCAN/MIXED/COMPLEX/IMAGE_PDF；router映射到pymupdf/paddleocr/mineru；COMPLEX非MinerU服务拒绝 |
| 输出 | ParseResult（ok、pdf_type、evidence_mode、pages、error） |
| 异常 | ZERO_PAGES/ENCRYPTED/CORRUPT不可重试；OCR_FAILED/MINERU_FAILED/RETRYABLE_IO可重试 |
| 代码位置 | `parser/parser.py、detector.py、router.py、pymupdf_extractor.py、ocr_paddle.py、mineru_adapter.py、models.py` |

### 4.2 Classification（`classifier/`）

| 项 | 内容 |
|---|---|
| 职责 | 证据路由、相关性门禁、两级分类、校验、LLM自动复核 |
| 输入 | ParseResult |
| 核心处理 | route_evidence选模式并截断；gate打分分流；L1直判或LLM四选一；L2经reranker直判或LLM三选一；verify校验归属互斥；AutoReviewer补supplement复核 |
| 输出 | ClassificationResult（含result_type、L1/L2、scores、source、basis、版本） |
| 异常 | 空证据/embedding失败进UNCERTAIN；OCR低置信进UNRESOLVED；LLM失败进FAILED；未校准阈值强制MANUAL_REVIEW |
| 代码位置 | `classifier/pipeline.py、evidence.py、gate.py、levels.py、verify.py、review.py、knowledge.py、config.py` |

### 4.3 Backend（`backend/`）

| 项 | 内容 |
|---|---|
| 职责 | 任务建模、结果校验入库、分页查询、人工复核回写 |
| 输入 | 扫盘请求、Worker结果字典、复核补丁 |
| 核心处理 | uuid5幂等建任务；save_result强校验类别携带规则；query_results分页；apply_review仅MANUAL_REVIEW可写 |
| 输出 | 任务状态、结果列表/详情、复核确认 |
| 异常 | 非法result_type、CLASSIFIED缺类别、非CLASSIFIED带类别均400拒绝 |
| 代码位置 | `backend/app.py、schemas.py、store.py、models.py、auth.py、migrations/001_init.sql` |

### 4.4 Scheduler（`scheduler/`）

| 项 | 内容 |
|---|---|
| 职责 | 队列流转、阶段编排、重试与断点续跑、GPU互斥 |
| 输入 | task_id引用、parse_ref引用 |
| 核心处理 | RedisQueue以seen集合去重；Pipeline按STAGES推进，失败仅重跑当前阶段语义；resume_pending/pending_from续跑；GPUPool避免抢卡 |
| 输出 | 阶段推进后的任务状态、死信记录 |
| 异常 | 非RETRYABLE直接DEAD；RETRYABLE≤3次重试，超限进queue:dead |
| 代码位置 | `scheduler/pipeline.py、queue.py、handoff.py、gpu_lock.py、resources.py` |

### 4.5 DevOps（`deploy/`）

| 项 | 内容 |
|---|---|
| 职责 | 单机多GPU容器编排、监控、运维脚本 |
| 输入 | Compose配置、环境变量、模型/PDF挂载 |
| 核心处理 | 8服务编排；GPU0/1归OCR、GPU2归MinerU、GPU3归推理；PDF只读挂载；workdata/modelcache持久化；worker按WORKER_ROLE启动 |
| 输出 | 可一键拉起的运行环境（配置已完成，未真实部署验证） |
| 异常 | 显存不足、镜像缺失、挂载缺失按运维指南排查 |
| 代码位置 | `deploy/docker-compose.yml、Dockerfile.*、worker_main.py、ops.sh、gpu_check.sh、prometheus.yml` |

## 5 代码目录结构

```text

```

## 6 部署与可靠性

部署架构：单Linux服务器，CPU承载API/Parser/Postgres/Redis，GPU0/1为OCR、GPU2为MinerU、GPU3为BGE-m3+reranker+LLM网关。Redis仅传引用（上限2000字节），全文经文件引用流转。

| 能力 | 实现 |
|---|---|
| 幂等 | 任务uuid5、同路径去重、队列seen去重 |
| 重试 | 可重试错误≤3次；LLM调用30s超时×重试2 |
| 断点续跑 | 按DocTask.stage与pending_from续跑，不重扫全量 |
| 异常结果 | FAILED可重试；UNRESOLVED/MANUAL_REVIEW进人工 |
