# 一、项目概述

现有约900万份PDF已存放在服务器上。系统以只读方式访问原文件，对文本PDF、扫描PDF、复杂版式PDF及图片型PDF进行自适应解析，依据既有业务目录自动判断相关性和一级、二级类别，形成可追溯分类结果。

## 1.1 建设目标

自动识别文件是否属于指定业务分类体系，不得将无关文件强制归档。

对相关文件先完成一级分类，再在所属一级下完成二级分类。

优先利用标题、章节及原文关键段落形成分类依据，支持无标题和纯图片文档。

低置信度、相邻类别边界冲突和证据不足情况进入大模型裁决或人工复核。

保留原始文件路径、证据片段、模型与规则版本、分数及最终结果，实现审计追溯。

## 1.2 系统边界

本期建设范围为服务器既有PDF的识别和分类；不包含原PDF迁移、重建文件存储、不要求自动改写原PDF。人工复核和分类知识库管理需提供可用的操作入口。

## 1.3 预期交付

交付包括：完整分类知识库、解析与分类服务、任务调度、结果导出与查询、人工复核功能、测试报告、性能Benchmark、部署及运维手册。

# 二、分类目录与数量

目录规模：4个一级类别、25个二级类别。一级与二级映射固定并可配置维护；必须遵循先一级后所属二级的层级约束。

# 三、核心业务流程

文件扫描/任务生成 → PDF有效性与类型识别 → PyMuPDF/PaddleOCR/MinerU分流解析 → 统一结构化内容 → Evidence Router证据选择 → Relevance Gate相关性判定 → 一级分类 → 一级内二级候选召回与精排 → 证据一致性检查 → 结果保存或人工复核。

## 3.1 证据路由规则

禁止把整篇长正文不加筛选地作为唯一输入；也禁止只依赖标题中是否命中关键词。分类证据应保留原文出处（页码/段落）。

# 四、相关性判断（Relevance Gate）

## 4.1 判断目标

先判定文档是否落在上述4个一级、25个二级类别的业务覆盖范围。输出 RELEVANT（相关）、IRRELEVANT（无关）或 UNCERTAIN（无法确定）；UNCERTAIN由受约束的LLM辅助裁决，仍不能确认则进入人工复核。

## 4.2 判断依据

分类语义：证据与整个分类知识库中业务定义、典型对象和业务动作的语义匹配程度。

领域特征：是否出现具有区分度的业务对象及其具体业务动作，不能只凭“通知、工作、管理”等通用词。

主题集中度：匹配信息是否反映文档主要目的，而非正文中的偶然引用或附件内容。

证据质量：标题清晰度、正文可读性、OCR置信度和视觉证据可靠性。

分数校准：查看候选的绝对匹配分及与无关样本的差异；Top1与Top2差距主要反映类别歧义，不能单独作为是否相关的证据。

重要边界：综合管理覆盖较广，“没有安全生产关键词”不等于无关；同样，文件提到一个业务术语也不代表其主旨相关。仅当对全体系的匹配持续低、无明确业务证据且质量充分时，才允许直接判无关。

# 五、一级分类判定

一级分类以“文件主要解决什么业务问题”为准，核心依据是文档主旨、主要业务对象、主导业务动作、所属一级定义及原文证据；不得凭单个名词出现次数判断。

## 5.1 算法与裁决

规则识别对象/动作并提示候选 → BGE-M3匹配4个一级类的业务定义 → 得分清晰且证据一致时直接接受 → 候选接近或主旨冲突时LLM只在候选一级范围内裁决 → 无法裁决则复核。阈值以标注测试集校准，不能将示例模型分数当作固定概率。

# 六、二级分类判定

二级分类仅在已经确定的一级类别子集内进行。BGE-M3根据二级类别定义、对象、动作、边界与典型案例召回Top5；Cross-Encoder Reranker对候选精排；明确领先且文本一致则直接接受，接近/冲突时将Top3及证据交给LLM选择或返回UNCERTAIN。

# 八、异常、边界和人工复核需求

无关文件：必须能够输出IRRELEVANT，不能把综合管理作为所有未知文件的兜底类别。

多主题文档：以唯一主责事项确定单标签；无法判断主责事项则人工复核。若实际需要多标签，应另立需求。

无标题/泛标题：改用正文段落，不因缺标题直接失败。

纯图片：OCR不足时使用视觉理解，降低自动接收力度；视觉证据不足则人工复核。

OCR质量低、文件损坏、加密不可读：按可重试异常和不可恢复异常区分，终态为FAILED或MANUAL_REVIEW。

题文冲突：不能只按标题归档；对冲突重新获取证据并判定，必要时人工复核。

# 九、结果数据要求

# 十、验收与测试要求

验收使用独立人工标注的代表性测试集，必须包含普通文本、扫描、复杂版式、无标题、纯图、无关及边界冲突文件。分类效果不得仅在能自动分类的简单样本上统计。

准确率和自动分类率目标应在首批样本标注、业务评审及性能测试完成后正式签署，不应把尚未验证的数字写为既定达标承诺。

# 十一、实施步骤与职责分工

# 十二、需业务方确认的决策事项

分类是单标签还是允许同一PDF跨类别多标签？当前方案按单标签设计。

遇到“专业对象”与“综合执法职能”冲突时优先遵循何种主管职责？

机构内部采购、财务、宣传材料在何种条件下应归综合管理，何种条件下应判无关？

灾害防治、灾后物资保障、现场救援调度间的优先归档原则如何明确？

验收目标采用哪种精确率、覆盖率和人工复核成本折中？

结论：该需求的关键不仅是采用BGE、Reranker及LLM，而是将4个一级、25个二级类别建设为具备定义、边界、反例和可追溯证据的正式分类知识库，并通过相关性门控防止无关文件被强行归类。
