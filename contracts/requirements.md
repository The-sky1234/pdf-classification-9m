# 需求规格说明（requirements.md）

版本 V1.0-planner | 来源：docs/三份文档 | 本轮只做规划，不开发业务代码。

## 1. 目标
对服务器既有约900万PDF只读处理：自适应解析（文本/扫描/复杂版式/纯图片）→ 相关性判断 → 一级分类 → 所属一级内二级分类 → 可追溯结果。允许输出无关与人工复核，不强制归档。

## 2. 系统边界（硬约束）
- 只读访问原文件；不迁移、不复制、不改写原PDF；系统仅存轻量化结果。
- 不含原PDF迁移/重建存储；人工复核与知识库管理需可用入口（一期可先做最小可用）。
- 一期不训练自有监督模型；以知识库+规则+BGE-M3+Reranker+疑难LLM为主；复核积累后二期再议。

## 3. 分类目录（严格）
4个一级、25个二级，映射固定（安全生产7 / 应急救援3 / 综合管理9 / 防灾减灾救灾6），详见 taxonomy.yaml。
终态另有三类非分类标签：IRRELEVANT（无关文件）、MANUAL_REVIEW（人工复核）、FAILED（处理失败）。

## 4. 核心流程
扫描/任务生成 → 有效性与类型识别 → PyMuPDF/PaddleOCR/MinerU分流 → 统一结构化 → Evidence Router → Relevance Gate → 一级 → 一级内二级（BGE Top5→Reranker→疑难LLM Top3）→ 正文一致性校验 → 保存或复核。

## 5. 证据与相关性规则
- 禁止整篇长正文不筛选作唯一输入；禁止只看标题关键词。
- 证据保留页码/段落出处；无标题/泛标题转正文；纯图片OCR不足用视觉描述并提高自动通过门槛。
- Relevance Gate输出 RELEVANT/IRRELEVANT/UNCERTAIN；综合语义匹配、领域对象+动作、主题集中度、证据质量；Top1-Top2差距只反映歧义，不单独证明无关；综合管理不得作兜底。

## 6. 结果与验收
结果字段见 data-contract.md；状态机见 state-machine.md；接口见 api-contract.yaml。
验收须用独立标注集，覆盖文本/扫描/复杂版式/无标题/纯图/无关/边界冲突；准确率与自动率目标待首批标注+评审+Benchmark后签署，本轮不承诺具体数字。

## 7. 业务确认结论（2026-10-08 用户已确认）
1. 单标签制（已确认）：每PDF以唯一主责事项确定单标签；无法判断主责则MANUAL_REVIEW。
2. 对象/职能冲突（已确认）：根据文件主责业务、分类职责边界综合判断，不搞一刀切。
3. 内部采购/财务/宣传（已确认）：机构业务归属与主责事项优先。机关预算/决算/经费→规划财务；新闻发布/宣传报道→新闻宣传；普通办公采购/后勤→综合办公；信息化建设→科技和信息化；救灾物资采购/储备/调拨→救灾和物资保障；其他专项采购按实际主责；明显无关→IRRELEVANT；无法明确→LLM仍不定则MANUAL_REVIEW。
4. 灾害三环节（已确认）：主要业务目的优先、阶段辅助。预防/监测/防治→防灾减灾救灾对应二级；现场响应/指挥/实时调度→指挥调度；灾后救助/安置/物资保障→救灾和物资保障；综合文件看标题/章节/核心任务定主责，不定→LLM→MANUAL_REVIEW。
5. 验收折中（已确认）：balanced折中路线，精确率/覆盖率/复核成本平衡，具体数值以首批标注+评审+Benchmark后签署为准。
6. 二级定义草案中对象优先/职能优先/灾种救援边界冲突规则须专家评审后生效。（仍待专家评审）
